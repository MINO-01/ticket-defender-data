# score-v2-exp2 사전 등록

상태: 사전등록 고정 및 구현 반영. 합성 fixture smoke는 실행했으며, 독립 holdout 평가는 미실행.

`score-v2-exp2`는 `score-v2-exp1`을 대체하지 않는 별도 실험 모델이다. 점수는 조사
우선순위이며 불법 가능성, 동일인 여부 또는 제재 결론이 아니다. 이 문서는 합성 또는
holdout 결과를 보기 전에 고정한다. 결과를 본 뒤 아래 값, 임계값, 지표를 변경하지 않는다.

## 고정 식별자와 파라미터

- score version: `score-v2-exp2`
- projection version: `projection-v2.2-exp2-ipwindow-softhub`
- IP 시간창: 회차 범위와 UTC 구매 시각 기준 600초
- 상대 허브 임계값: 범위 계정 수의 1%
- 규모 항: `0.6 + 0.4 * min(log2(n) / 5, 1)`
- 수량 중립값: `0.5`
- 반복 포화: 회차 수 4
- 보고 band: HIGH `0.40`, MEDIUM `0.20`

| 신호 | r | k | H |
| --- | ---: | ---: | ---: |
| refund_account_hash | 0.80 | 10 | 없음 |
| phone_hash | 0.70 | 5 | 없음 |

`H`가 있는 신호는 `n >= max(H, ceil(scopeAccounts * 0.01))`에서 투영하지 않는다.
`H`가 없는 환불계좌와 연락처 신호에는 hard exclusion을 적용하지 않는다. 남은 신호의
감쇠는 `n <= k`이면 1, 그 밖에는 `sqrt(k/n)`이다. 두 계정 이상이 공유한 토큰만 관계를
만든다.

## 점수와 설명

각 신호의 coverage를 `c_s`, 평균 감쇠를 `dbar_s`라 할 때 다음을 보존한다.

```text
L = 1 - product(1 - r_s * dbar_s * c_s)
G = 0.6 + 0.4 * min(log2(n) / 5, 1)
Q = mean(min(effectiveQuantity / confirmedLimit, 1)) 또는 0.5
R = min((performanceCount - 1) / 3, 1)
B = 0.5 * Q + 0.5 * R
S = round(L * G * B, 4)
```

결과는 `L`, `G`, `B`, `Q`, `R`, 가용 및 제외 신호, coverage, 수량 상태와 사유를
함께 보존한다. `Q=0.5`는 한도 정책 또는 수량 완전성이 확인됐다는 뜻이 아니다.
noisy-OR 신호 독립성도 실험 모델의 가정일 뿐이다.

## 평가 경계

평가기는 분석 결과를 동결한 뒤 별도 truth 파일을 읽는다. 계정 및 군집 precision을
섞지 않으며, 군집 precision@K, 정상 반례의 최고 순위, 신호별 ablation을 출력한다.
GDS를 실행하지 못한 경우 NetworkX 대체 결과를 GDS PASS로 표기하지 않는다.

알려진 한계는 10분 창 경계, 정책 부재에서의 수량 중립값, 회차 하나일 때 `R=0`, 그리고
IP와 결제 신호만으로 회차 간 집단을 연결하지 않는다는 점이다.

## 부록 A. 모의 실험 평가 계획

### A.1 목적과 평가 자료 분리

이 부록은 exp2를 모의 예매 실험에서 평가할 기준을 정한다. 점수와 등급은 조사 우선순위이며 암표 판정이나 불법 확정이 아니다. 개발용 S1부터 S8까지의 합성 자료와 팀 리허설 자료는 구현 확인에만 쓴다. 평가용 두 회차 자료는 점수, 임계값, 규칙을 선택하거나 수정하는 데 사용하지 않는다.

두 평가 회차 각각에 대해 분석 담당자는 exp2 결과를 정답과 대응표 없이 동결하고 결과 파일과 설정 식별값의 SHA-256을 기록한다. 두 회차의 모든 exp2 및 exp3 결과 동결이 끝난 뒤에만 실험 진행자가 정답 파일을 열어 채점한다. PR 6의 freeze 단계는 정답과 PR 7 대응표를 읽지 않는다. score 단계만 봉인된 정답 및 합성 실험용 계정 대응표를 사용할 수 있다. 원본 CSV, 정답 파일, 대응표와 키는 저장소 밖에 둔다.

### A.2 평가 단위와 순위

평가 후보는 분석 도구가 출력한 원본 후보 행이다. E4 표시용 상위 후보 묶음은 평가 후보를 합치거나 대체하지 않으며, 표시 묶음 전후 효과는 별도 참고 결과로 보고한다. 도구가 출력한 후보를 평가자가 사후에 부분집합 또는 겹침 기준으로 합치지 않는다. 동일 후보 식별자가 중복 출력되면 평가 전 조용히 제거하지 않고 입력 또는 출력 무결성 문제로 기록한다.

후보 순위는 점수 내림차순, 그 다음 정렬된 계정 ID 튜플 오름차순으로 정한다. 계정 ID는 실험용 대응표를 적용해 평가 안에서만 비교하며 보고물에는 원래 ID를 넣지 않는다. 같은 후보가 서로 다른 성격의 근거를 가진 경우에도 원본 후보 행을 유지한다.

정답 역할은 `SCALPER_*` 암표 집단, `NORMAL_*` 정상 역할, 그 외 미확정 역할로 구분한다. 집단 품질 지표에서는 미확정 계정을 제외하고, 미확정 정답 계정 수와 상위 K 후보 중 미확정 계정을 포함한 후보 수를 별도로 보고한다. 실제 검토 비용 계산에는 미확정 계정도 포함한다.

### A.3 집단 매칭과 지표

예측 후보 P와 정답 집단 T의 교집합 크기를 I라 할 때 IoU는 I / |P ∪ T|, 정답 집단 재현율은 I / |T|로 계산한다. I가 0인 쌍은 매칭할 수 없다. 두 조건을 모두 만족하는 쌍만 매칭 가능하다.

- IoU 0.5 이상
- 정답 집단 재현율 0.8 이상

정답 암표 집단과 예측 후보는 최대 cardinality 1대1로 매칭한다. 후보별 매칭 대상이 같을 때 IoU 내림차순, 정답 집단 ID 오름차순으로 기존 결정 순서를 유지한다.

주 지표는 `groupPrecision@5`다. 보조 지표는 `groupPrecision@3` 및 `groupPrecision@10`이다. 각 K에서 원본 후보 순위 상위 K행만 선택하며, 알려진 정답 역할 계정이 한 명 이상 포함된 후보만 분모에 둔다. 알려진 계정이 없는 후보를 제외하더라도 K 이후 후보로 보충하지 않는다. 집단 정밀도는 상위 K의 평가 가능 후보 중 1대1 매칭된 후보 수를 평가 가능 후보 수로 나눈 값이다. 분모가 0이면 N/A다. 암표 정답 집단이 0개이면 집단 재현율은 N/A이며, 평가 가능한 후보가 있고 매칭이 0이면 집단 정밀도는 0이다.

집단 재현율은 상위 K 후보와 매칭된 암표 정답 집단 수를 전체 암표 정답 집단 수로 나눈 값이다. 분모가 0이면 N/A다. 기존 `precision@20`은 군집 단위 참고 지표로 그대로 유지하며, 집단 단위 정밀도로 이름이나 의미를 바꾸지 않는다.

### A.4 정상 집단 HIGH 노출

기존 고정 등급을 사용한다. HIGH는 S가 0.40 이상, MEDIUM은 0.20 이상 0.40 미만이다. 이 기준을 새로 조정하지 않는다.

정상 집단 HIGH 수는 전체 동결 후보 중 HIGH 후보와 IoU 0.5 이상 및 정상 정답 집단 재현율 0.8 이상을 만족하는 고유 정상 정답 집단 수로 정의한다. 한 HIGH 후보가 암표 집단과 1대1 매칭되더라도 정상 집단 노출 계산에서는 제외하지 않는다. 정상 정답 집단 간에는 1대1 제한을 적용하지 않으며, 한 집단은 여러 후보에 노출되어도 한 번만 센다. 전체 정상 정답 집단 수와 노출 집단 수를 함께 보고한다.

HIGH 후보에 포함된 고유 정상 계정 수도 별도 보조 지표로 센다. 현재 정답 구조가 정상 계정별 집단 ID를 보존하지 않는 경우, 정상 집단 ID와 계정 소속을 포함하는 합성 정답 계약을 후속 PR 6에서 구현한다. 해당 계약과 지표가 구현되기 전 결과는 미구현으로 기록한다.

### A.5 조사 비용과 미확정 정답

주 조사 비용은 상위 K 원본 후보 계정의 합집합에 있는 고유 계정 수를 그 K 안에서 매칭된 정답 암표 집단 수로 나눈 값이다. 후보 사이에 반복된 계정은 한 번만 세며 미확정 계정도 실제 검토 비용에 포함한다. 매칭된 정답 집단이 0개면 비율은 N/A로 하고 분자인 고유 검토 계정 수는 그대로 보고한다.

정답 집단별 최초 발견 비용은 주 매칭에서 해당 집단과 연결된 후보의 순위까지 검토한 후보들의 계정 합집합 크기로 별도 보고한다. 미확정 계정도 포함하고 중복 계정은 한 번만 센다. 상위 K 안에서 매칭되지 않은 정답 집단은 비용을 만들지 않고 상위 K 안 미발견으로 기록한다.

### A.6 H1부터 H7까지의 가설과 판정

기존 가설을 유지한다.

- H1: exp2에서 각 암표 역할 집단 G1, G2, G3의 최고 순위가 가족 반례 F1, F2의 최고 순위보다 높다.
- H2: 같은 공연 데이터에서 exp2의 기존 `precision@5`가 v2보다 높다. 새 `groupPrecision@5`로 H2 정의를 대체하지 않는다. 비교 실행 결과가 없으면 판정 불가다.
- H3: 기존 계획의 3일차 공연 B에서 P1과 P3의 역할을 바꾸고 새 브라우저 프로필을 사용한 조건에서도 H1이 유지된다. 당일 역할 교대는 날짜와 공연 차이가 없는 별도 조건이며 H3를 대체하지 않는다. 변경안은 사전등록 승인 전까지 확정하지 않는다.
- H4: 판매 시작 한 시간 뒤 같은 집 IP에서 따로 예매한 정상 계정이 어떤 후보에도 연결되지 않는다.
- H5: LTE 기기의 IP 시간창 토큰을 다른 참가자와 공유하지 않는다.
- H6 탐색: 실습실 같은 Wi-Fi를 쓰는 정상 계정이 암표 후보에 포함되는지 그대로 보고한다.
- H7 탐색: 참가자가 자원을 분산할 때 후보 순위가 내려가는지 그대로 보고하고 한계를 기록한다.

원래 계획의 날짜, 공연, 장소, 역할 교대, 브라우저 조건 또는 필요한 입력을 충족하지 못한 가설은 임의의 유사 조건으로 대체하지 않고 판정 불가로 기록한다. 해당 조건에서 나온 합성 결과가 있으면 본 실험 판정과 분리한다. 연구윤리 절차의 확인과 필요한 승인이 끝나기 전에는 사람 참여 실험을 진행하지 않는다.

### A.7 구현과 재현성 한계

현재 `exp2_compare.py`의 후보 구성은 연결요소와 Union-Find 기반 연구용 proxy다. 이는 NetworkX Louvain이나 실제 GDS Louvain 결과가 아니다. GDS를 실행하지 못한 결과는 proxy 결과 또는 미실행으로 표시하고 GDS 결과라고 부르지 않는다. 현재 도구에서 산출하지 못하는 `groupPrecision@3`, 정상 집단 HIGH 노출, 고유 계정 검토 비용은 후속 PR 6 구현 대상으로 남긴다.

이 문서의 기준일은 문서 작성일이다. 실제 기준 고정 시점은 승인된 부록 커밋과 이후 별도 승인된 `exp2-frozen` 태그의 커밋 해시 및 시각으로 기록한다. 기준일을 태그 고정일로 간주하지 않는다.
