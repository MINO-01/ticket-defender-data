# V1A LFR Louvain parity procedure

The registered matrix is 1,000 and 5,000 nodes, μ in 0.1 through 0.6 by 0.1, and seeds 20261101 through 20261110: 120 trials. LFR uses τ1=3, τ2=1.5, average degree 10, and community size 20 through 100. A failed graph generation is saved as a failed trial; the runner never substitutes a more successful seed. NetworkX Louvain and Neo4j GDS 2.6.6 receive the same topology, undirected orientation, unit weights, and resolution 1.0. NetworkX uses the registered graph seed; GDS uses concurrency 1 because its Louvain API exposes no RNG seed parameter. Community truth labels remain in the evaluator process and are never stored as graph properties or sent to either algorithm.

Install the optional pinned dependency with `python -m pip install -r evaluation/track1/requirements-lfr.txt`. The preregistered NetworkX-only smoke is `python -m evaluation.track1.lfr_parity --seed 20261101 --mu 0.1 --nodes 1000 --output <new-output>/v1a-lfr.json`. It reports NetworkX as completed and GDS as `BLOCKED_GDS_NOT_CONFIGURED`; this is not a GDS pass. The full 120-trial matrix is opt-in with `--matrix`.

For the GDS smoke, use `tests/run_gds_integration.ps1` with `-LfrOutputPath <new-output>/v1a-lfr.json`. Add `-LfrMatrix` only for the registered 120 trials. The wrapper provides the verified ephemeral Neo4j/GDS 2.6.6 container and invokes the runner with its loopback Bolt URI. The runner checks the isolated-container guard again, creates uniquely named synthetic nodes, projects the relationships undirected, verifies node and edge completeness, records both algorithm runtimes, modularity, community count, ARI/NMI, and drops its projection and fixture nodes in a `finally` block. Never set a non-loopback URI or reuse an application database.

LFR ARI/NMI measure algorithm partition agreement with synthetic graph truth. They do not measure ticket-level or group-level detector accuracy. Those outcomes are reported separately by the frozen exp2 comparison evaluator.
