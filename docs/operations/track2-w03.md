# W03 Track 2 listing extraction operations

This implementation belongs to issue #21 and is a dormant internal analysis component. It does not start fan report jobs, read W02 private objects, match reservations, create Cases, adjudicate illegal resale, or issue PDFs. The [v1 listing contract](../api/track2-listing-context-v1.md) is the provider-facing proposal; no Spring consumer has been connected.

## Chosen design and alternatives

The seat v1 route and listing v1 route have separate DTOs. A replaceable provider returns structured candidates; Pydantic and deterministic rules reject extra properties, invalid types, inconsistent states, unsupported prices and quotes that do not contain claimed values. This is the combination of separate contracts and VLM plus server validation. Extending only the seat DTO would silently break existing consumers and merge unrelated meanings. OCR-only rules could avoid external model transfer but need their own image-quality benchmark and parser for varied listing layouts; they remain a candidate for the later provider decision. Provider switching is localized to the `VLMProvider` protocol.

The configured model identifier defaults to `gemini-3.8-flash`, whose [official model card](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) lists image input and structured output. The pinned local SDK is `google-genai==2.25.0`. The account-specific model entitlement, Korean listing accuracy, latency, and live adapter behavior have **not** been tested. The [provider pricing page](https://ai.google.dev/gemini-api/docs/pricing) is dynamic; cost depends on image/input and output tokens and any retried calls. The service caps output at 2,048 tokens, has a default of two concurrent calls per process, at most three attempts, a 15-second per-attempt limit and a 35-second total limit. Only 429 and transient 5xx provider errors and timeouts retry. Invalid JSON, semantic validation failures and permanent 4xx errors do not retry. The SDK adapter explicitly limits its own retries to one attempt so it does not multiply service retries.

The Gemini adapter uses the SDK's asynchronous `generate_content` and a structured response schema. These are implementation capabilities, not evidence of listing accuracy. No live measurements of Korean image understanding, cost per report or latency exist, so a provider cannot be declared production suitable from W03 tests. A later provider comparison must measure those properties on approved synthetic or lawfully processed data and review each candidate's processing, retention and transfer terms. The protocol permits a compliant alternative or local analysis.

The model is not a visual proof system. `FOUND` means an output candidate passed server shape and quote/value consistency checks. A fabricated value accompanied by a fabricated matching quote may pass. There is no independent OCR or human pixel comparison in W03, and `reviewRequired` stays true. No downstream component may turn that candidate into a confirmed event, performance reference, ticket, illegal sale, or sanction. `UNKNOWN` means the value was not established; `FAILED` means the analysis process failed. They cannot be interchanged.

## Deployment boundary

Both POST routes pass through `VLMPreBodyGate` before FastAPI parses JSON. The gate checks `VLM_ENABLED`, a separate `VLM_INTERNAL_SHARED_SECRET` of at least 32 bytes, and one `X-TD-Internal-Key` header with constant-time comparison. Missing or bad credentials are rejected before body consumption. The body limit is 7 MiB, and image-specific encoded, decoded and pixel limits apply after authentication. The legacy seat route keeps WebP, while the listing route accepts only JPEG/PNG. Application limits do not replace gateway byte, connection and rate limits. TLS plus a private network or restrictive ingress are mandatory for deployment. A shared secret grants service-level access, not tenant authorization; Spring must verify evidence ownership and scope before calling.

For this single trust domain MVP, a high-entropy shared secret needs no identity issuer and can be checked before body parsing. It gives every holder the same service access, so rotation and narrow distribution are essential. Service JWTs could express caller identity, expiry and audience but require signing, validation, rotation and clock policy across services; no such issuer exists in the Python contract. mTLS authenticates the peer at the transport layer and supports stronger infrastructure identity, but needs certificate issuance, rotation and ingress configuration. Neither alternative replaces Backend tenant and evidence authorization. The shared secret is the approved MVP choice, and TLS plus network restriction remain mandatory.

The defaults `VLM_ENABLED=false`, `VLM_EXTERNAL_CALLS_ENABLED=false`, and `VLM_PROVIDER=disabled` fail closed. Even with route access enabled for isolated Fake Provider tests, default dependency configuration returns `MODEL_PROVIDER_UNCONFIGURED`. `GEMINI_API_KEY` is not an internal authentication secret. Model and internal secrets belong in a secret manager or environment injection, never source, logs, sample requests, or CI. Do not enable live provider flags merely because the adapter exists. Full provider use is outside W03 approval.

W02 accepts evidence up to 20 MiB per file; listing analysis accepts 5 MiB decoded and legacy seat analysis accepts at most 3,932,160 decoded bytes. A stored report whose image exceeds W03 limits remains an accepted report and needs a separate analysis error or manual-review state in future Spring integration. Python does not alter the W02 storage record or make a private URL public.

## Privacy and provider release gate

Only synthetic images and fake provider responses are used in W03. Do not submit actual fan reports, ticket QR codes, reservation numbers, names or other personal data. The [Gemini API terms](https://ai.google.dev/gemini-api/terms?hl=en), including developer eligibility and applications possibly used by minors, need counsel and product review before use. The service must also establish customer-specific processing grounds, the external provider's processing and retention terms, any processor/subprocessor agreement, international transfer obligations under [Korean Personal Information Protection Act article 28-8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034292881), notices, deletion and audit rules. Paid-tier data-use terms alone do not complete that review. The alternative can be a legally suitable provider or self-hosted OCR/VLM. No W03 flag represents legal approval.

## Tests and CI

From the repository root with Python 3.13.3 and `requirements.txt` installed:

```powershell
.\venv\Scripts\python.exe -B -m unittest discover -s tests
```

The suite uses FastAPI TestClient and fake providers. It needs no Gemini key, actual Gemini account, MinIO, or Neo4j for unit and contract checks. `tests/test_track1_gds_integration.py` requires isolated `TD_GDS_TEST_URI` and `TD_GDS_TEST_PASSWORD`; without them its six tests are **skipped**, never counted as passed. Do not point them at existing Neo4j data. The PR workflow runs the same unit and contract suite on Python 3.13.3 with the external provider disabled and no credentials. `actions/checkout` and `actions/setup-python` are pinned to verified commits from their repositories; dependencies are version-pinned in `requirements.txt`, but hash-locked package installation and full software composition analysis remain future supply-chain work. The local workflow YAML has been parsed, but an actual GitHub-hosted run requires a user Push and PR.

## Next integration contract

Spring must add an authenticated internal caller, verify `fanReportId` to `evidenceId` membership, tenant/event ownership, private object bytes and stored digest, decide which evidence is eligible for external analysis, and store extraction revisions without overwriting source facts. It must map non-2xx `FAILED` errors to a retry or review workflow and preserve accepted intake independently. Actual provider selection, legal clearance, real-image tests, customer-specific access controls and production observability are separate release gates.
